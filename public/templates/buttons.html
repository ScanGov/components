Buttons

Two button styles and one size rule. The rules for choosing between them are in the buttons skill in ScanGov/skills. If a design seems to need a third style, change this stylesheet for every site; do not add a variant to a page.

Primary

The one main action on a view: a form submit, Save, Send, Get started. One per view, placed first. Brand fill and border; hover brightens and lifts, the fill stays.

Get started Small 
<a href="..." class="btn btn-primary">
  <i class="fa-solid fa-rocket" aria-hidden="true"></i> Get started
</a>
<button type="submit" class="btn btn-primary">Save</button>

Secondary

Everything else: going to another page, Cancel, Close, Edit, Remove, Copy, Download. A quiet border at rest; hover, focus and active invert the fill and the border together.

Demo Small 
<a href="..." class="btn btn-outline-primary">
  <i class="fa-solid fa-wand-magic-sparkles" aria-hidden="true"></i> Demo
</a>
<button type="button" class="btn btn-outline-primary">Copy link</button>

Icons

Leading, decorative (aria-hidden="true"), one per button. The icon always matches the label in every state and theme, whatever its own color rule is outside a button. The button's gap spaces it, so no margin classes. An icon-only button keeps an aria-label that contains the visible word.

GitHub Demo 
<a href="..." class="btn btn-outline-primary" aria-label="Demo">
  <i class="fa-solid fa-wand-magic-sparkles" aria-hidden="true"></i><span class="d-none d-md-inline">Demo</span>
</a>

Size

Default everywhere. btn-sm only inside a table row or a toolbar, such as the page actions row. There is no large size.

Not buttons

Tabs and view switchers use nav-pills or nav-tabs with no btn classes (see nav-tabs.html). Pagination, accordion headers, the menu toggler, the close X and btn-check toggles are Bootstrap components and are not part of this system.

Destructive actions

Remove and Delete are secondary buttons that open a confirmation. The confirm button in that step is the only place btn-danger is used.
